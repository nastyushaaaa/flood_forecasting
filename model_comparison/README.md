# Сравнение моделей прогноза уровня воды

Все модели проекта проверяются в одинаковых условиях: на одном периоде, на одних и тех же днях и одними метриками. Поэтому их результаты можно честно сравнивать.

## Как запустить

Из корня репозитория:

```bash
pip install -r requirements.txt
python -m model_comparison.run_all
```

Прогон занимает около 10 минут, дольше всех обучается бустинг. Результаты сохраняются в `model_comparison/results/`.

## Вход и выход

**Вход:** общий файл данных `data/amur_khabarovsk_clean_2002-2026.csv` и модели из `predict.py`.

**Выход** (`model_comparison/results/`):

| Файл | Задача | Что внутри |
|---|---|---|
| `metrics.csv` | 2.4 | Метрики всех моделей по горизонтам 1–14 сут |
| `metrics_by_phase.csv` | 2.6 | То же отдельно для половодья, паводка и межени |
| `mae_by_horizon.png` | 2.7 | График MAE по горизонтам для всех моделей |
| `best_by_horizon.csv` | 2.8 | Лучшая модель на каждом горизонте: за весь год и в каждой фазе |
| `predictions.csv` | 2.3 | Каждый прогноз каждой модели (около 8 МБ, в git не кладём, получается запуском) |

## Что где лежит

| Файл | Задача | Что делает |
|---|---|---|
| `config.py` | 2.2 | Период проверки 02.08.2025–01.08.2026, обучение до 01.08.2025, горизонты 1–14 сут |
| `metrics.py` | 2.1 | Все метрики в одном месте: MAE, S (RMSE), NSE, S/σΔ, P% |
| `pairs.py` | 2.3 | Пары «день выпуска → горизонт → проверяемый день», одни и те же для всех моделей |
| `models.py` | 2.3 | Обучает каждую модель из `predict.py` и спрашивает у неё `predict(дата, h)` для всех пар |
| `phases.py` | 2.5 | Фаза водного режима для каждой даты |
| `run_all.py` | 2.3–2.8 | Запускает всё по порядку и сохраняет результаты |

## Правила проверки

- Модели обучаются только на данных до 01.08.2025 включительно. Исключение — PG-LSTM: используется готовая сеть из `amur_pg_lstm/model/`, обученная на данных до 2018 года. В период проверки она тоже не заглядывает.
- Для каждого дня проверки и каждого горизонта h прогноз выпускается за h суток до этого дня. Дни, где уровень восстановлен, а не измерен, в проверку не берутся. Всего 4951 пара.
- σΔ (насколько обычно меняется уровень за h суток) считается по обучающему периоду.
- Инерционный прогноз («уровень не изменится») — точка отсчёта. Модель полезна, если она точнее него.

## Метрики

| Метрика | Что значит | Хорошо, когда |
|---|---|---|
| MAE, см | Средний промах | меньше |
| S (RMSE), см | Средний промах, крупные ошибки весят сильнее | меньше |
| NSE | 1 — идеально, 0 — не лучше среднего уровня | ближе к 1 |
| S/σΔ | Критерий Росгидромета | ≤ 0,5 хорошо, ≤ 0,8 удовлетворительно |
| P, % | Доля оправдавшихся прогнозов (ошибка ≤ 0,674·σΔ) | больше |

## Фазы водного режима

Границы заданы по месяцам, по средним уровням у Хабаровска за 2002–2026 годы:

- **половодье** — апрель–май (таяние снега, ледоход);
- **паводок** — июнь–сентябрь (дождевые паводки, пик в августе);
- **межень** — октябрь–март (спад и низкая зимняя вода).

Границы меняются в словаре `PHASE_BY_MONTH` в `phases.py`.

## Ограничения

- Бустинг в `alex_gpb/flood.py` обучен только на 1 и 14 сут. Для сравнения он обучается тем же способом на каждый горизонт 1–14 (см. `predict.py`).
- Статистические тренды и Prophet не знают текущего уровня, их прогноз зависит только от даты. На коротких горизонтах они проигрывают даже инерционному прогнозу.
- Фазы определены по календарю, а не по фактическим датам начала и конца половодья.
