# Пять моделей посуточного прогноза уровня Амура в Хабаровске

Расчёт по `amur_khabarovsk_clean_2002-2026.csv`. Цель — `level_khabarovsk`.
Единственная объясняющая переменная — время. Метеоданные и другие гидропосты не используются.

## Готовые результаты

- `amur_five_models.xlsx` — Excel с пятью отдельными листами моделей, расчётными формулами, стандартными ошибками и проверкой на отложенном периоде.
- `results/daily_forecast.csv` — ежедневный прогноз пяти моделей со стандартной ошибкой отдельного будущего наблюдения и условными 95%-ными границами.
- `results/model_metrics.csv` — стандартная ошибка остатков, MAE и RMSE проверки, R² и корреляция остатков на лаге 1.
- `results/validation.csv` — фактические и прогнозные уровни за проверочный период.
- `results/calibration.json` — коэффициенты, обратные информационные матрицы, параметры расчёта, версии Python-пакетов и SHA-256 исходного CSV.
- `data/` — неизменённый исходный CSV.

## Даты и выборка

Исходный ряд: 01.01.2002–01.08.2026, 8 979 строк. В оценку включены 8 595 строк с `level_khabarovsk_filled = 0`. 384 строки с флагом 1 сохранены, но исключены из оценки и сумм квадратов ошибок. Календарный индекс не сжимается при исключении строк.

Окончательные коэффициенты оценены по всему доступному периоду, без подбора окна. Прогноз рассчитан на 30 дней: **02.08–31.08.2026**. Более поздних наблюдений в исходном файле нет. Это прогноз из точки 01.08.2026, а не прогноз от текущей календарной даты.

Единицы уровня и нулевая отметка поста в CSV не описаны. Все значения сохранены в исходной шкале, без объявления их сантиметрами или абсолютной высотой. Перед сопоставлением с отметками затопления нужно подтвердить единицы и систему отсчёта.

## Функции и оценка

`t` — календарный номер дня: 01.01.2002 соответствует t=1.
`x = t/1000` — положительное время в тысячах дней.
`u = 2*(t-1)/(T-1)-1`, где T — календарная длина обучающего периода. Это масштабирование времени для устойчивого расчёта полиномов, без добавления факторов.

| Файл | Функция | Параметров p |
|---|---|---:|
| `polynomial2.py` | H = a0 + a1*u + a2*u² | 3 |
| `polynomial3.py` | H = a0 + a1*u + a2*u² + a3*u³ | 4 |
| `power.py` | H = a*x^b | 2 |
| `logarithmic.py` | H = a + b*ln(x) | 2 |
| `exponential.py` | H = a*exp(b*x) | 2 |

У всех моделей минимизируется сумма квадратов ошибок **в исходной шкале уровня воды**. Уровни не логарифмируются, не сдвигаются и не обрезаются снизу. Поэтому отрицательные исходные уровни не теряются.

Полиномы и логарифмическая модель линейны по параметрам: Python использует `numpy.linalg.lstsq`, Excel — нормальные уравнения с показанными матрицами и формулами их обращения. Степенная и экспоненциальная модели оцениваются нелинейным МНК. Сначала проводится профильный поиск по b в [-10,10] с точным расчётом a при каждом b, затем уточнение `scipy.optimize.least_squares` с аналитическим якобианом. Минимум проверяется на удалённость от границ поиска. Это численная оценка, а не доказательство единственности глобального минимума.

Чистые степенная и экспоненциальная функции при x>0 сохраняют знак a. Такая форма не может воспроизвести все переходы исходного уровня через ноль. Свободный сдвиг уровня к этим двум моделям не добавлялся, чтобы сохранить заказанные функции.

## Стандартная ошибка

Для каждой модели:

`SSE = Σ(H_i − Hhat_i)²`, только для строк с флагом 0.

`s = sqrt(SSE/(n-p))` — стандартная ошибка остатков.

`J` — матрица производных функции по оцениваемым параметрам. Для линейных по параметрам моделей J совпадает с матрицей регрессоров X.

`Cov(beta) ≈ s² * inverse(J'J)`.

`SE_mean(h) = sqrt(g_h' * Cov(beta) * g_h)` — стандартная ошибка оценённого среднего тренда.

**`SE_prediction(h) = sqrt(s² + g_h' * Cov(beta) * g_h)`** — стандартная ошибка отдельного будущего суточного уровня, которую запрашивали в задании.

`g_h` — вектор производных функции на прогнозную дату. В Excel он показан в колонках N:Q каждого модельного листа.

Условный 95%-ный предиктивный интервал: `Hhat(h) ± t(0.975,n-p)*SE_prediction(h)`. Это не интервал только для среднего тренда. Для нелинейных моделей ковариация и границы приближённые, по линеаризации.

Эти формулы предполагают адекватную спецификацию функции и независимые ошибки с постоянной дисперсией; для t-интервалов используется нормальное приближение/нормальность ошибок. В данном ряду корреляция соседних остатков около 0,997. Следовательно, эти условия не подтверждены и приведённые SE и 95%-ные границы **не являются откалиброванной оценкой паводкового риска**. Временная зависимость остатков, сезонность и гидрологические факторы в пяти заказанных трендах не моделируются.

## Проверка вне обучающей выборки

Одна фиксированная точка начала прогноза — 02.07.2026. Обучение только на наблюдениях до этой даты включительно. Проверка: **03.07–01.08.2026**, 30 дней. На протяжении этих 30 дней модели не дообучаются. Для проверочных полиномов масштаб u рассчитан только по периоду обучения.

Это одна проверка на горизонтах 1–30, а не многократная проверка однодневных прогнозов. Её результаты не показывают качество на всех сезонах и годах.

| Модель | s остатков, ед. CSV | RMSE проверки | MAE проверки |
|---|---:|---:|---:|
| Полином 2 | 161,92 | 172,34 | 145,01 |
| Полином 3 | 161,81 | 189,58 | 164,45 |
| Степенная | 163,72 | 142,72 | 113,54 |
| Логарифмическая | 162,51 | 163,80 | 135,69 |
| Экспоненциальная | 165,60 | 133,66 | 104,85 |

Для сравнения: постоянный прогноз последнего известного на 02.07.2026 уровня 105 даёт RMSE 180,02 на том же периоде. Это дополнительная контрольная линия, а не шестая оцениваемая функция.

На выбранной проверке минимальный RMSE у экспоненциальной модели. Этого недостаточно, чтобы признать её лучшей для всех периодов или для применения кредитными организациями. Расчёт оценивает уровень воды; вероятность затопления конкретного объекта и финансовый ущерб здесь не рассчитаны.

## Использование Excel

В текущей версии книги шесть листов: сводка и пять моделей. Листы «Расчет ряда» и «Исходные» удалены. В таблицах качества оставлены только R² на обучающей истории и MAE на проверочных 30 сутках.

1. Откройте `amur_five_models.xlsx` в Excel.
2. На листе **Сводка** измените ячейку B3: горизонт от 1 до 90 дней. Прогнозные строки пересчитаются. Основной график показывает первые 30 дней выбранного горизонта.
3. На отдельных листах моделей колонки D:H содержат прогноз, его SE, нижнюю/верхнюю условные 95%-ные границы и SE среднего тренда.
4. Коэффициенты и вспомогательные статистики сохранены по первоначальной оценке. После удаления исходных листов книга не переобучает модели на новых данных. Для повторной оценки используйте Python.
5. При ручном изменении коэффициентов прогнозная функция изменяется, но сохранённая оценка стандартной ошибки не переоценивается. CSV не меняется при редактировании Excel.

## Повторный запуск Python

Из корня репозитория в PowerShell / терминале:

```bash
python -m pip install -r requirements-models.txt
python run.py
```

Другой горизонт, например 60 дней:

```bash
python run.py --horizon 60
```

Воспроизводится калибровка и файлы CSV/JSON в `results/`. Скрипт не перезаписывает Excel: после замены исходного CSV книгу нужно обновить отдельно. Стандартная библиотека `unittest` запускает включённые численные проверки:

```bash
python -m unittest discover -p "test_*.py"
```

Для готового расчёта использованы Python 3.12.14, NumPy 2.3.5, pandas 2.2.3, SciPy 1.17.0. Полные версии также находятся в `calibration.json`.

## Загрузка на GitHub через браузер

Модели, скрипт запуска, Excel и документация размещаются в корне репозитория. Исходный CSV находится в `data/`, результаты — в `results/`. Скрипт запускается из корня командой `python run.py`.

1. Скачайте и распакуйте `flood_models_github.zip`.
2. Откройте https://github.com/nastyushaaaa/flood_forecasting и выберите базовую ветку `new_main`.
3. Создайте от неё ветку `water-level-models`.
4. В корне новой ветки выберите **Add file → Upload files**.
5. Выделите всё содержимое распакованного архива: отдельные файлы, папки `data` и `results`. Перетащите именно это содержимое в окно загрузки. Не загружайте сам ZIP или внешнюю папку распаковки.
6. Убедитесь, что отображаются пути `run.py`, `amur_five_models.xlsx`, `data/amur_khabarovsk_clean_2002-2026.csv` и `results/daily_forecast.csv`.
7. Введите сообщение **Add five water level forecasting models** и нажмите **Commit changes**.
8. Откройте **Pull requests → New pull request**: base `new_main`, compare `water-level-models`. Создайте PR.
9. Во вкладке **Files changed** проверьте расположение файлов в корне. Если раньше в этой ветке уже были загружены дополнительные внешние каталоги для моделей, удалите прежние копии до слияния PR.

Если нет прав записи, сначала создайте **Fork** репозитория. Загрузите файлы в корень своей копии, затем создайте PR в `nastyushaaaa/flood_forecasting`, base `new_main`, через **compare across forks**.
